**Assistant:**

TC = Linux **Traffic Control**. It's a kernel subsystem for classifying and acting on packets at the network interface level.

In this context:

- **`clsact` qdisc** — a special qdisc (queuing discipline) that lets you attach filters to ingress (incoming) and egress (outgoing) on an interface without actually queuing
- **`flower` classifier** — matches packets by fields like `dst_ip`, `ip_proto`, `dst_port`, `eth_type` etc.
- **`mirred` action** — either **mirror** (copy + forward, original continues) or **redirect** (move packet, original dropped)

So `tc filter add dev eth0 ingress ... flower dst_ip <ct_ipv6> action mirred egress redirect dev grpc-uplink` means:

> On packets arriving at `eth0`, if the IPv6 destination is the container's address → redirect the packet out `grpc-uplink` (into the container) instead

It runs entirely in kernel space, no userspace involvement per-packet. On a single-queue virtio_net it's effectively equivalent to XDP in terms of throughput, and it composes cleanly — multiple filters on the same interface just match in priority order, no chaining/dispatcher needed.

    ovsdb.ensure_initialized().await.context("OVSDB not reachable")?;
    let gw_str = cfg.gw.to_string();
    // 1. Set management address on bridge BEFORE touching the uplink
    let _ = rtnetlink::del_ipv4_address(&cfg.br, &cfg.mgmt_addr, cfg.mgmt_prefix).await;

    // 2. Gateway host route (no onlink for host/32)
    run_ignore("ip", ["route", "replace", &gw_str, "dev", &cfg.br]);
    // 3. Default route onlink
    rtnetlink::add_default_route_onlink(&cfg.br, &gw_str).await?;
    // 4. Add UPLINK to bridge as AF_XDP
    let ports = ovsdb.list_bridge_ports(&cfg.br).await.unwrap_or_default();
    if !ports.contains(&cfg.uplink) {

    }
    // 5. Flush UPLINK addresses
    let _ = rtnetlink::flush_addresses(&cfg.uplink).await;
