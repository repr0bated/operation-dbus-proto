**Assistant:**

This is a really elegant fit. Three layers:

---

**1. CozoDB as the OSCAL graph store**

OSCAL's data model is naturally a graph — controls reference parameters, profiles reference catalogs, SSPs reference components which reference controls. CozoDB's Datalog is perfect for this:

```datalog
:create oscal_control {
    id: String,       =>
    family: String,
    title: String,
    params: Json,
    baseline: String  // fedramp-moderate, high, etc
}

:create control_implementation {
    control_id: String,
    component: String,  =>
    status: String,     // implemented | partial | planned
    narrative: String,
    tags: [String]
}

:create control_finding {
    control_id: String,
    component: String,  =>
    risk: String,
    poam_ref: String
}
```

Query like: *"show all partial controls tagged `net` that are FedRAMP Moderate required"* — one Datalog clause.

---

**2. Tag routing as the enforcement bridge**

The existing three tag classes (OSCAL / 3tched / UI) already have OSCAL as a first-class routing axis. Every plugin mutation that goes through the enforcement point gets tagged with the control IDs it touches — `AC-2`, `SC-7`, etc. Tag router then:
- Checks CozoDB: is that control `implemented`?
- If `partial` or `planned` → log to audit, maybe block depending on policy
- Feeds findings back into `control_finding` automatically

So compliance state is **derived from actual system mutations**, not manually authored.

---

**3. Gemma for local narrative generation**

Sensitive compliance data (SSP narratives, finding descriptions) shouldn't leave the host. Gemma running locally via `gemini_fallback.rs` (or swapped for a local Gemma endpoint) does:
- Generate implementation narratives from structured plugin state
- Gap analysis: *"component X satisfies AC-2(a) but not AC-2(b) — here's what's missing"*
- Draft POA&M entries from `control_finding` rows

No API call, no data egress.

---

**The flow:**

```
Plugin mutation
  → tag router (OSCAL tags attached)
  → CozoDB upsert (control_implementation status updated)
  → Gemma: generate/update narrative if status changed
  → cognitive-mcp: query SSP state via ask_question / dbus_query_core
```

The `OscalAuditorAgent` and `ComplianceTrestleAgent` become the query/authoring interface on top of this live CozoDB graph — instead of static guidance, they're querying real system state.
