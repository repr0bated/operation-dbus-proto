Ghostbridge — WireGuard Zero-Trust Identity Pipeline

How WireGuard-derived session identity is stamped, stripped, injected into gRPC headers, and validated without the tunnel ever entering the service mesh.

The Concert Analogy. You arrive at the venue and hand your keys to the valet (WireGuard gateway). The valet parks your car and gives you a claim ticket (session ID). At the door, that ticket is exchanged for an all-access wristband (the IdentitySled). Every backstage door checks the wristband — not your car, not your ticket, just the wristband. The hologram on the wristband proves it was issued by tonight's venue, not last week's. Your car never enters the building. The WireGuard tunnel is dropped at the gate; only the cryptographic stamp rides through.

⑤ GhostbridgeInterceptor
Backstage door — wristband scanner

Tonic gRPC middleware on port 18789. Every call hits this before any handler. op-grpc-bridge/src/interceptor.rs:34

pub fn ghostbridge_interceptor(req: Request<()>) -> Result<Request<()>, Status> {
    // 1. Wristband must be present
    let footprint = req.metadata().get("x-ghostbridge-footprint");
    let trace_id  = req.metadata().get("x-ghostbridge-trace-id");
    if footprint.is_none() || trace_id.is_none() {
        return Err(Status::unauthenticated(
            "A.N.N.A. Scribe: Missing Ghostbridge Identity Sled. Connection Dropped."
        ));
    }

    // 2. Zero-copy mmap read — no DB, no network, just tmpfs
    let (sled_ptr, _mmap) = op_identity::read_sled()?;
    let sled = unsafe { &*sled_ptr };

    // 3. Hologram check — footprint must match TONIGHT's schema
    let expected = hex::encode(sled.hashed_footprint);
    if request_footprint != expected {
        return Err(Status::permission_denied(
            "A.N.N.A. Scribe: Temporal Hash Mismatch. Session footprint out of sync."
        ));
    }

    // 4. Stamp trace ID into gRPC extensions — rides every downstream call
    req.extensions_mut().insert(trace_id);
    Ok(req)
}

Validity rule: sled is live only when hashed_footprint != [0u8;32] AND trace_id != [0u8;16]. A zero field means the wristband was never properly stamped — instant ejection, no exception.

The mmap read is zero-copy — the guard glances at your wrist under UV in microseconds with no external calls.

Key Design Decisions

Why the PSK does NOT rotate on login

Rotating the PSK on each authentication event would cause a race condition where in-flight WireGuard sessions using the old PSK fail cryptographic verification mid-stream — locking out active peers. The PSK uses a fixed salt (b"WG-STABLE-PSK-2024") so the parking spot number never changes between visits. Per-session freshness is provided by the ephemeral session key (derived via server nonce), not the PSK.

Why the WireGuard subnet is dropped before gRPC

The /32 subnet assignment (10.100.0.x) is purely a cryptographic identity label — it tells OpenFlow which Incus container to route to. It is not a routable address inside the service mesh. Forwarding WireGuard packets into the gRPC layer would require every service to understand the WireGuard protocol. Instead, xray strips the transport and re-expresses identity as two HTTP/2 metadata headers that any gRPC interceptor can validate without WireGuard awareness.

Why the footprint is Blake3 of schema state

The footprint binds the wristband to the current configuration epoch. If the schema mutates (new routes, revoked peers, updated policies), the footprint changes. Any session carrying the old footprint is immediately invalidated at the next gRPC call — no explicit revocation list required. The mutation index ([32..40] in the sled) provides ordering for conflict resolution.
