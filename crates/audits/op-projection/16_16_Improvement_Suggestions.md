1. **Suggestion**: Precompile and Cache Policy and Constraint Regular Expressions | **Rationale**: In `enforce_policy` and `validate_permissions`, regular expressions are parsed and compiled on every single access control request using `Regex::new(&policy.resource_pattern)?`. Similarly, `validate_constraints` recompiles the pattern `Regex::new(pattern)` on every single schema field validation. Regex compilation is highly CPU-intensive. Precompiling these regular expressions when policies or schemas are registered and storing them in thread-safe, compiled structures would eliminate a massive hot-path performance bottleneck. | **Example**: `crates/op-projection/src/access_control.rs:52` and `crates/op-projection/src/schema_engine.rs:610`

2. **Suggestion**: Replace Unbounded In-Memory History and Audit Storage with Persistent DB Storage (CozoDB/Sled) | **Rationale**: The `ProjectionAccessController` stores an unbounded list of authorization decisions in `audit_trail: Arc<RwLock<Vec<AccessControlAudit>>>`. Similarly, `ProjectionStore` tracks the complete history of mutated projections in `history: Arc<DashMap<String, Vec<HistoricalProjection>>>`. Since these structures reside purely in-memory and grow continuously with every transaction, they will inevitably trigger Out-of-Memory (OOM) panics in long-running production environments. Transitioning to a local embedded database like CozoDB or Sled with a rolling pruning window is critical for production sustainability. | **Example**: `crates/op-projection/src/access_control.rs:20` and `crates/op-projection/src/projection_store.rs:23`

3. **Suggestion**: Transition Ad-Hoc Dynamic JSON Data Contracts to Schema-as-Code Protobuf/OSCAL Definitions | **Rationale**: The `RawEntity::data` and `Projection::data` fields are represented as untyped, unstructured `simd_json::OwnedValue` dynamic payloads. This forces downstream consumption code to validate schemas using ad-hoc, dynamic parsing rules in Rust code rather than relying on compile-time types or statically compiled serialized contracts. Transitioning these structures to strictly versioned, protobuf-backed structures or OSCAL compliance schemas would enforce API compatibility guarantees across plugins, DBus, and UI subscribers. | **Example**: `crates/op-projection/src/interfaces.rs:90` and `crates/op-projection/src/plugin_reader.rs:136`

4. **Suggestion**: Replace Fragile DBus XML Parsing with Schema-Driven Serialization Parser | **Rationale**: The `SystemDbusReader` parses XML payload schemas returned from D-Bus introspection by looping over text lines and performing an ad-hoc substring match `line.contains("<node name=\"")` and splitting. This ad-hoc string parsing is fragile and fails if formatting, namespaces, or properties on node nodes deviate from arbitrary expected whitespace. A proper deserializer utilizing `quick-xml` mapped to a structured, versioned Rust data model should be used instead. | **Example**: `crates/op-projection/src/dbus_reader.rs:49`

5. **Suggestion**: Refactor Synchronous Readers to Eliminate Inefficient Tokio "Block-on" Overheads | **Rationale**: `SystemPluginReader` executes the synchronous `SourceReader::read_all` trait contract by manually invoking `.block_on()` using `tokio::task::block_in_place` or building a temporary, single-threaded current-thread runtime on-the-fly. This model is highly inefficient, limits concurrent execution, and can easily panic if executed on thread-starved runtime workers. The core `SourceReader` trait should either be natively async or utilize non-blocking connection pools. | **Example**: `crates/op-projection/src/plugin_reader.rs:356`

6. **Suggestion**: Optimize State Materialization Paths to Leverage Zero-Copy Payloads (`Arc<Value>` or `Bytes`) | **Rationale**: In the hot path of state ingestion, `ProjectionSystemEngine::build_projection` and `ProjectionAccessController::enforce_policy` perform heavy memory allocations by cloning the entirety of complex deeply nested JSON objects (`projection.clone()` and `data.clone()`). In low-latency stream materialization context (where sub-50ms processing guarantees are target metrics), these constant allocations fragment heap memory. Wrapping payloads in `Arc<Value>` or utilizing reference-counted zero-copy `Bytes` buffers would resolve these overheads. | **Example**: `crates/op-projection/src/access_control.rs:45` and `crates/op-projection/src/projection_engine.rs:31`

7. **Suggestion**: Add Memory Alignment and Concurrency Verification for Shared Memory Sled Access | **Rationale**: `IdentitySledReader::read_sled_entity` performs a direct, unchecked pointer cast on shared memory pointer references: `let sled = unsafe { &*ptr };`. If the memory alignment constraints of `IdentitySled` are violated on different target architectures, or if another host process modifies the memory space concurrently without synchronization barries, this triggers undefined behavior (UB) or data corruption. Implementing memory verification signatures, size-checks, and memory-safe atomic alignment wrappers (e.g. via `bytemuck`) is highly recommended. | **Example**: `crates/op-projection/src/sled_reader.rs:62`

8. **Suggestion**: Streamline Redundant Keepalive Mechanisms in SSE Axum Server | **Rationale**: The SSE streaming server implements a manual keepalive heartbeat stream via `stream::repeat_with(|| Ok(Event::default().comment("keepalive"))).throttle(Duration::from_secs(30))` and merges it with updates. However, Axum's `.keep_alive(KeepAlive::new())` is already appended downstream on the Sse stream, which makes this manual keepalive stream redundant. Furthermore, combining standard select streams with infinite repeat streams can introduce performance lag and stream multiplexing bugs. Removing the manual repeat stream simplifies the network implementation. | **Example**: `crates/op-projection/src/json_stream.rs:253`

9. **Suggestion**: Replace String-Typed Permissions and Actions with Strongly Typed Enum/Newtypes | **Rationale**: Requester permissions are represented as raw, stringly-typed arrays (`pub permissions: Vec<String>`), and actions are passed as unconstrained string slices (`action: &str`). This pattern is highly susceptible to typos, bypass bugs (e.g., case mismatch or injection characters), and makes maintenance of policies difficult. Enforcing a structured permission model or newtypes (e.g., `Permission` and `Action` enums) prevents policy evaluation errors at compile-time. | **Example**: `crates/op-projection/src/data_models.rs:524`

10. **Suggestion**: Implement Structured Trace Context Propagation across System Readers and Access Controller | **Rationale**: High-concurrency operations within `access_control.rs` and `dbus_reader.rs` lack tracing context propagation. While `log_decision` logs output messages, they do not correlate with an active parent OpenTelemetry or tracing span. This prevents operations engineers from correlating access decisions or device read performance issues with end-to-end tracing spans across the D-Bus, procfs, and SSE stream systems in production. Structured fields using `tracing::info_span!` should be added. | **Example**: `crates/op-projection/src/access_control.rs:118` and `crates/op-projection/src/dbus_reader.rs:34`
