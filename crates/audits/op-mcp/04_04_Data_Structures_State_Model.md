## 2. Schema-as-Code Discipline Compliance

Flagged occurrences where data contracts are expressed as ad-hoc, free-form structs, unstructured JSON, or dynamic string structures rather than versioned Protocol Buffers or OSCAL standard schemas:

### 1. Ad-Hoc JSON-RPC Representations
- **File:Line**: `crates/op-mcp/src/protocol.rs:11-23`, `crates/op-mcp/src/protocol.rs:49-61`, `crates/op-mcp/src/protocol.rs:94-100`
- **Description**: The core MCP client-server request/response loop uses JSON-RPC types (`McpRequest`, `McpResponse`, `JsonRpcError`) derived as ad-hoc Serde structs with untyped `simd_json::OwnedValue` as parameter values.
- **Remediation**: Use the structured, versioned types defined in the generated `.proto` file (`crates/op-mcp/src/grpc/generated/op.mcp.v1.rs`) for all transport layers.

### 2. Ad-Hoc Tool Schemas
- **File:Line**: `crates/op-mcp/src/agents_main.rs:88-348`, `crates/op-mcp/src/tools/filesystem.rs:31-38`, `crates/op-mcp/src/tools/ovs.rs:49-140`
- **Description**: Tool input schemas are specified using free-form, inline raw JSON literals (e.g., `json!({ "type": "object", ... })`). These schemas can easily diverge between the server implementation and the client expectations.
- **Remediation**: Use strongly typed `ToolSchema` and `ToolParameter` Protobuf messages (`crates/op-mcp/src/grpc/generated/op.mcp.v1.rs`) to construct and validate schemas deterministically.

### 3. Dynamic Tool Adapter Mapping
- **File:Line**: `crates/op-mcp/src/grpc/service.rs:184-240`
- **Description**: The gRPC service layer translates raw `simd_json::OwnedValue` to/from dynamic `prost_types::Value` / `prost_types::Struct` types at runtime. This violates structural type safety.
- **Remediation**: Establish compilation-time code generation of schemas for each individual system tool (e.g., filesystem, network, database) instead of routing them through dynamic runtime structural mappings.

## 3. Direct Security Vulnerability Audit

### CRITICAL: Remote Authentication Bypass via Spoofed Host Header
- **File:Line**: `crates/op-mcp/src/transport/http.rs:90-101` and `crates/op-mcp/src/transport/http.rs:118`
- **Description**: The HTTP Axum-based authentication middleware `wireguard_auth_middleware` allows unauthenticated access to the endpoint if `is_localhost_host` evaluates to `true`. However, `is_localhost_host` determines loopback status solely by inspecting the HTTP `Host` header sent by the client. Because the HTTP `Host` header is fully controlled by the client, a remote attacker can bypass authentication on the public network interface by transmitting a request with a spoofed `Host: localhost`, `Host: 127.0.0.1`, or `Host: ::1` header.
- **Impact**: Any remote attacker can send requests to `/tools/call` and `/mcp` without providing a WireGuard bearer token, resulting in complete unauthorized access to the system control plane.
- **Remediation**: Do not use the HTTP `Host` header to determine loopback trust. Instead, verify the actual connection peer IP address using Axum's `ConnectInfo` extractor to ensure it matches loopback interface ranges.

```rust
// VULNERABLE CODE (crates/op-mcp/src/transport/http.rs)
fn is_localhost_host(headers: &HeaderMap) -> bool {
    headers
        .get("host")
        .and_then(|v| v.to_str().ok())
        .map(|h| {
            let host = h.split(':').next().unwrap_or(h);
            host == "127.0.0.1" || host == "localhost" || host == "::1"
        })
        .unwrap_or(false)
}
```

### CRITICAL: Arbitrary Command Execution & Filesystem Overwrite via `RequestHandler` Blocklist Bypass
- **File:Line**: `crates/op-mcp/src/request_handler.rs:303` (and referenced in `crates/op-mcp/src/request_context.rs:218`)
- **Description**: The Unified MCP Server in `server.rs` implements a security blocklist (`BLOCKED_PATTERNS`) to restrict dangerous mutating tools like `shell_execute`, `write_file`, and mutating systemd/OVS tools. However, the alternative `RequestHandler` implementation in `request_handler.rs` registers these exact mutating tools (`ShellExecuteTool`, `WriteFileTool`, `OvsAddBridgeTool`, etc.) and does *not* apply any blocklist filtering when calling `execute_tool` via its compact meta-tool `execute_tool` path.
- **Impact**: An attacker who can execute tool calls through `RequestHandler` can pass `tool_name = "shell_execute"` or `"write_file"` with arbitrary arguments to execute arbitrary shell commands or overwrite system configurations as the system user.
- **Remediation**: Enforce `BLOCKED_PATTERNS` strictly in `RequestContext::execute_tool` or ensure `RequestHandler` routes tool execution through the identical security filter used by `McpServer`.

```rust
// VULNERABLE DIRECT EXECUTION PATH (crates/op-mcp/src/request_handler.rs)
async fn meta_execute_tool(&self, ctx: &RequestContext, args: Value) -> Result<Value> {
    let tool_name = args.as_object().and_then(|o| o.get("tool_name")).and_then(|v| v.as_str())
        .ok_or_else(|| anyhow::anyhow!("Missing tool_name"))?;
    let arguments = args.as_object().and_then(|o| o.get("arguments")).cloned().unwrap_or(json!({}));
    
    ctx.execute_tool(tool_name, arguments).await // Bypasses server.rs blocklist entirely!
}
```

### HIGH: Potential Undefined Behavior / Crash via `unsafe simd_json::from_str` on Untrusted Inputs
- **File:Line**: `crates/op-mcp/src/external_client.rs:344`, `crates/op-mcp/src/external_client.rs:414`, `crates/op-mcp/src/http_server.rs:282`, `crates/op-mcp/src/agents_main.rs:549`
- **Description**: The codebase frequently calls `unsafe { simd_json::from_str(&mut buffer) }` on dynamically received, mutable string buffers. `simd_json` requires specific internal memory alignment, trailing padding bytes, and valid UTF-8 structures to guarantee safe parsing. Performing `unsafe` parsing directly on buffers populated from external, untrusted network responses or processes without explicit padding/validation violates these invariants.
- **Impact**: An external MCP server returning highly customized, non-standard payloads, or an attacker corrupting standard streams, can trigger memory out-of-bounds reads/writes or process crashes.
- **Remediation**: Use the safe, non-mutating parsing APIs or ensure that parsed strings are generated internally, or switch to standard `serde_json` for processing untrusted external inputs.

---

### MEDIUM: Authentication Bypass / Exposure of Local Host Control via Stderr Logging
- **File:Line**: `crates/op-mcp/src/external_client.rs:115`
- **Description**: The external MCP client spawns command lines specified directly within configuration structs using `tokio::process::Command`. If configuration files can be influenced or modified by privileged local or remote users, this leads to immediate command injection.
- **Remediation**: Restrict the `command` field in `ExternalMcpConfig` to a strict, hardcoded enumeration of allowed binaries, or validate that executable targets reside inside read-only system binary paths (e.g., `/usr/bin`).
