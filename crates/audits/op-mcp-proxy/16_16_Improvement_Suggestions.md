1. **Suggestion:** Offload Blocking Subprocesses and Synchronous File I/O to a Dedicated Threadpool or Use Async APIs | **Rationale:** The asynchronous runtime threads are currently blocked by synchronous execution commands (`Command::new("wg")`) and blocking file reads (`std::fs::read_to_string`). In a high-throughput proxy environment, blocking executor threads stalls other asynchronous tasks. These operations should be migrated to `tokio::process::Command` and `tokio::fs`, or wrapped explicitly in `tokio::task::spawn_blocking`. | **Example:** `crates/op-mcp-proxy/src/session.rs:115` and `crates/op-mcp-proxy/src/gcloud_auth.rs:196`

2. **Suggestion:** Replace Ad-Hoc Offsets in Sled Slicing with a Shared Schema Struct | **Rationale:** The zero-copy memory reader maps `/dev/shm/plugin_schema.dat` and parses binary data using ad-hoc hardcoded slices and byte offsets (e.g. `&bytes[192..208]`). This violates the schema-as-code discipline. If the producer (`op-identity::schema_bridge`) changes its internal struct alignment or layout, this reader will silently read corrupted offsets. Both crates should share a versioned, common struct annotated with `#[repr(C)]` or serialize via a shared versioned schema protocol. | **Example:** `crates/op-mcp-proxy/src/sled.rs:49`

3. **Suggestion:** Migrate Local Ad-Hoc Rusqlite Table Creation to Workspace-Standard CozoDB | **Rationale:** The session manager initializes and queries local state tables using ad-hoc raw string SQL statements. The workspace defines a standardized relational graph storage module (`op-cozo-store` powered by CozoDB with Sled backend). Replacing the raw `rusqlite` implementation with CozoDB ensures query determinism, unifies the storage layers, and mitigates the use of raw SQL strings. | **Example:** `crates/op-mcp-proxy/src/session.rs:50`

4. **Suggestion:** Eradicate Untyped JSON Parameters in JSON-RPC & LLM Dispatch | **Rationale:** Stdin request parsing, tool execution routing, and direct LLM handling pass raw, unstructured `simd_json::OwnedValue` containers. Methods are evaluated as raw strings (e.g., `"sampling/createMessage"`), bypass compile-time contract safety, and increase parsing complexity. Introducing strongly-typed, versioned schemas (such as structs with `serde` deserialization or Protobuf contracts) ensures contract validation at the edge. | **Example:** `crates/op-mcp-proxy/src/direct_llm.rs:150` and `crates/op-mcp-proxy/src/main.rs:103`

5. **Suggestion:** Eliminate External Subprocess Spawning for WireGuard Peer Discovery | **Rationale:** To locate peer public keys, the system executes the external shell binary `wg show wg0 allowed-ips` and parses stdout strings. Spawning processes is highly expensive, does not scale under load, and relies on the execution path of the environment. Because the workspace already includes `rtnetlink` and `op-network`, peer configuration should be fetched directly using Netlink sockets or a memory-mapped peer-table lookup. | **Example:** `crates/op-mcp-proxy/src/session.rs:137`

6. **Suggestion:** Reduce Overhead of Transcoding and Cloning in Chat Message Iteration | **Rationale:** The `messages_to_simd` function performs redundant intermediate string parsing and allocations, converting `serde_json::Value` items back into `simd_json::OwnedValue` representations during HTTP completions. Working directly with raw parsed references or maintaining unified zero-copy serialization buffers would eliminate the CPU and garbage collection overhead of continuous JSON transcoding. | **Example:** `crates/op-mcp-proxy/src/http_server.rs:303`

7. **Suggestion:** Wrap Stdin JSON-RPC Loop in Tracing Spans with Injected Metadata | **Rationale:** The main server execution loop reads incoming RPC operations from stdin but fails to instrument each individual dispatch flow. Sled identity snapshots containing trace IDs and footprint hashes are loaded but omitted from standard request context. Creating a dedicated `tracing::span!` for each parsed JSON-RPC request and attaching these properties provides end-to-end trace context for all down-stream gRPC routing. | **Example:** `crates/op-mcp-proxy/src/main.rs:94`

8. **Suggestion:** Avoid Message Interpolation in Tracing Assertions | **Rationale:** Diagnostic logs regularly interpolate structured variables (such as errors or paths) directly into standard format strings. This decreases query performance in centralized telemetry systems where messages are indexed. These strings should be converted to structured key-value parameters. | **Example:** `crates/op-mcp-proxy/src/gcloud_auth.rs:136`
