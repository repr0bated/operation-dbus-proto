# Architecture & Module Map

### Overview
The `op-cognitive-mcp` crate implements a specialized Model Context Protocol (MCP) server that provides cognitive memory storage, dynamic content loading, a NotebookLM MCP bridge with gRPC ingress, and typed namespace tools. It utilizes CozoDB (via `op-cozo-store`) for relational/graph/vector persistence, Qdrant for semantic trace retrieval, and includes a fallback mechanism via the Google Gemini API.

### Module Tree
The library entry point is `crates/op-cognitive-mcp/src/lib.rs`. Its module hierarchy consists of the following 19 submodules:
*   `activity_filter` — Derives signaling significance and manages PII filters.
*   `cozo_shuttle` — Re-exports the shared CozoDB graph persistence layer.
*   `dbus_interface` — Exposes the MCP tool registry over the system D-Bus.
*   `rag_pipeline` — Ingestion pipeline (zip -> repomix parse -> enrich -> Voyage embed -> Qdrant).
*   `cognitive_tools` — Generic MCP tools backed by SQLite/Cozo memory namespaces.
*   `doctor` — Diagnostic diagnostics (auth status, quota, memory store, query history).
*   `gemini_fallback` — Fallback client using the Gemini API.
*   `grpc_service` — gRPC ingress endpoint mapping to NotebookLM and generic memory operations.
*   `memory_store` — Namespace-based CRUD memory backend over CozoDB.
*   `notebooklm` — Launches and wraps npm-based NotebookLM MCP sidecar over stdio.
*   `qdrant_shuttle` — Fetches semantic traces using shared memory identity mapping.
*   `quota` — Tracks API and tool usage against daily limits.
*   `server` — Dual-transport host coordinating HTTP/SSE and gRPC listeners.
*   `session` — Sliding context window query turn storage.
*   `tool_profiles` — Restricts exposed tools dynamically to optimize token budgets.
*   `typed_tools` — Enforces hardcoded project-level namespaces to prevent agent configuration errors.
*   `voyage` — Standard reqwest client for Voyage AI embeddings.
*   `proto` — Autogenerated tonic gRPC code.
*   `interceptor` — Interceptor checking WG pubkey/footprint matching on incoming gRPC.

### Entry Points
*   **Library:** `crates/op-cognitive-mcp/src/lib.rs`
*   **Daemon/Server Binary:** `crates/op-cognitive-mcp/src/main.rs`
*   **CLI Admin Binary:** `crates/op-cognitive-mcp/src/bin/op-cog-admin.rs`
*   **RAG Ingestion Binary:** `crates/op-cognitive-mcp/src/bin/rag-ingest.rs`

### Notes

# Production Security & Quality Audit Findings

## 1. CRITICAL: Shared Memory ABI Misalignment & Memory Access Corruption
### File References
*   `crates/op-cognitive-mcp/src/qdrant_shuttle.rs:16-24`
*   `crates/op-cognitive-mcp/src/interceptor.rs:5-18`

### Description
The shared memory file `/dev/shm/plugin_schema.dat` contains a binary `IdentitySled` struct shared across processes. However, the ABI definition of `IdentitySled` differs severely between the query loop and the gRPC interceptor:

**`crates/op-cognitive-mcp/src/qdrant_shuttle.rs:16`:**
```rust
#[repr(C)]
#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub struct IdentitySled {
    pub wireguard_pubkey: [u8; 32],
    pub mutation_index: u64,
    pub is_valid: bool,
    pub hashed_footprint: [u8; 32],
}
```

**`crates/op-cognitive-mcp/src/interceptor.rs:5`:**
```rust
#[repr(C)]
pub struct IdentitySled {
    pub wireguard_pubkey: [u8; 32],
    pub mutation_index: u64,
    pub is_valid: bool,
    pub _pad: [u8; 7],
    pub hashed_footprint: [u8; 32],
    pub schema_uuid: [u8; 16],
    pub subid: [u8; 64],
    pub control_source: [u8; 32],
    pub nextdns_profile: [u8; 16],
}
```

### Exploit Scenario / Impact
1.  **Padding and Offsets:** In `interceptor.rs`, the field `is_valid` is followed by explicit padding `_pad: [u8; 7]`. In `qdrant_shuttle.rs`, there is no padding field. Because `hashed_footprint` is an array of 32 `u8` bytes (alignment 1), the compiler does not inject implicit padding before it in `qdrant_shuttle.rs`.
2.  **Mismatched Reads:** When `qdrant_shuttle.rs` performs `std::ptr::read_unaligned(sled_ptr)`, it reads `hashed_footprint` starting at byte offset 41. However, the interceptor writes/reads `hashed_footprint` at byte offset 48.
3.  **Trace Spoofing/Bypass:** The semantic query logic in `qdrant_shuttle.rs:136` uses `hashed_footprint` to generate the active `trace_id` (`format_trace_id(sled.hashed_footprint)`). Due to this misalignment, `qdrant_shuttle.rs` will read 7 bytes of garbage padding plus the first 25 bytes of the footprint as the active trace ID. An attacker can manipulate padding variables or exploit mismatch states to bypass accountability checks or corrupt tracing queries.

## 2. CRITICAL: Unrestricted Directory Traversal & Arbitrary File Leakage via gRPC `AddFolder`
### File References
*   `crates/op-cognitive-mcp/src/grpc_service.rs:493-550`

### Description
The gRPC method `add_folder` allows a client to specify an arbitrary `folder_path` string:

```rust
let path = std::path::Path::new(&req.folder_path);
if !path.exists() || !path.is_dir() {
    return Err(Status::invalid_argument(...));
}
...
let walker = if req.recursive {
    walkdir(path)
} else {
    walkdir_shallow(path)
};
```

There is no path sanitization, sandboxing, or restricted directory validation. The walker recursively reads files directly from `req.folder_path` using `std::fs::read_to_string` and uploads them to the memory store under the target `notebook_id` namespace.

### Exploit Scenario / Impact
An authenticated client (or an attacker with valid credentials via spoofed credentials/keys) can supply `folder_path` as `/etc/` or `/var/lib/` or `/root/.ssh/`.
1.  The gRPC daemon will walk the targeted host directory, reading all files reachable by the process's privilege context.
2.  The files are inserted into the database as document keys.
3.  The attacker can then invoke `list_sources` and `get_source_content` to retrieve the contents of arbitrary system files (such as configurations, private keys, or passwords). This constitutes a massive remote data disclosure vulnerability.

## 3. CRITICAL: memory Unsafe Mmap Dereference in Interceptor (Denial of Service)
### File References
*   `crates/op-cognitive-mcp/src/interceptor.rs:27-38`

### Description
The gRPC `ghostbridge_interceptor` opens and memory-maps `/dev/shm/plugin_schema.dat`:

```rust
let file = File::open("/dev/shm/plugin_schema.dat")
    .map_err(|_| Status::internal("SchemaEngine Memory Unreachable"))?;

let mmap = unsafe {
    MmapOptions::new()
        .map(&file)
        .map_err(|_| Status::internal("Mmap failed"))?
};
let sled_ptr = mmap.as_ptr() as *const IdentitySled;

let is_valid = unsafe { (*sled_ptr).is_valid };
```

No size checks are performed on `mmap` before casting and dereferencing the pointer. The structure `IdentitySled` has a layout size of 216 bytes.

### Exploit Scenario / Impact
If `/dev/shm/plugin_schema.dat` is empty (0 bytes) or truncated (e.g., less than 216 bytes), the raw pointer dereference `(*sled_ptr).is_valid` reads past the end of the memory map boundaries. This triggers a `SIGBUS` or `SIGSEGV` error immediately, causing the entire gRPC server to crash. Any local unprivileged user who can truncate the shared memory file can shut down the system control plane daemon.

## 4. Schema-as-Code Violations (Ad-hoc Structs & Generic JSON)
### File References
*   `crates/op-cognitive-mcp/src/activity_filter.rs:190`
*   `crates/op-cognitive-mcp/src/memory_store.rs:72`
*   `crates/op-cognitive-mcp/src/grpc_service.rs:335`
*   `crates/op-cognitive-mcp/src/grpc_service.rs:502`

### Description
The codebase frequently uses unstructured or raw `serde_json::Value` fields and stringified JSON embedded inside protocol definitions instead of strongly typed, versioned Protobuf or OSCAL schemas.

*   **`activity_filter.rs:190`**: `pub payload: serde_json::Value` allows unvalidated JSON payloads for activity filtering.
*   **`memory_store.rs:72`**: `pub metadata: serde_json::Value` and `pub value: serde_json::Value` store unstructured JSON documents in the database.
*   **`grpc_service.rs:335`**: `metadata_json` is serialized back and forth as an ad-hoc JSON string in `GetNotebookResponse`.
*   **`grpc_service.rs:502`**: `components_json` packages health checks as generic JSON strings rather than a structured Protobuf message.

### Impact
This compromises contract enforcement, breaks structural validation guarantees, and increases the risk of runtime schema drift and decoding failures across workspace boundaries.

## 5. HIGH: Time-of-Check to Time-of-Use (TOCTOU) Race Condition in Deduplication
### File References
*   `crates/op-cognitive-mcp/src/activity_filter.rs:315-338`

### Description
The deduplication logic in `ActivityFilter::evaluate` checks for exact content-hash duplicates by acquiring a read lock:

```rust
let is_dup = self
    .window
    .read()
    .await
    .iter()
    .any(|e| e.content_hash == event.content_hash);

if is_dup && event.op_kind != OpKind::ToolCall {
    return Ok(FilterDecision::Suppress(SuppressReason::ExactDuplicate));
}
```

If it is not a duplicate, it releases the read lock, does some processing, and then acquires a write lock to insert the entry:

```rust
{
    let mut w = self.window.write().await;
    if w.len() >= tunables.dedup_window_max {
        w.pop_front();
    }
    w.push_back(WindowEntry { ... });
}
```

### Impact
Between releasing the read lock and acquiring the write lock, a concurrent execution thread can process an identical duplicate event. This TOCTOU race condition allows duplicate events to bypass the filter and end up recorded in the persistent snowball ledger.

## 6. MEDIUM: Insecure Permission Fail-Open on Critical Credentials
### File References
*   `crates/op-cognitive-mcp/src/grpc_service.rs:645-660`

### Description
During gRPC authorization setup via `setup_auth`, the program validates the file permissions of the supplied Chrome profile:

```rust
if mode & 0o077 != 0 {
    warn!(
        path = %req.credential,
        mode = format!("{:o}", mode),
        "Chrome profile has overly permissive permissions; should be 0o600"
    );
}
```

### Impact
If a file has world-writable permissions (`0o777`), the system logs a `warn!` message but **continues to run**. This fail-open behavior violates secure-by-default standards, letting compromised profiles persist inside active sidecars without forcing remedial administrative containment.

## 7. MEDIUM: Non-Atomic Rollover Flaw in Quota Manager
### File References
*   `crates/op-cognitive-mcp/src/quota.rs:55-66`

### Description
The `QuotaManager` implements query limits via an optimistic relaxed atomic transaction:

```rust
let current = self.queries_today.fetch_add(1, Ordering::Relaxed);

if current >= tier.daily_limit {
    // Roll back the increment — over quota
    self.queries_today.fetch_sub(1, Ordering::Relaxed);
    (false, 0, tier.daily_limit)
}
```

### Impact
Under highly concurrent client requests, hundreds of denied connections will concurrently increment the atomic counter `queries_today` before running `fetch_sub`. This causes the internal counter to artificially spike to extreme values. This temporary inflation can falsely deny legitimate requests and degrade throughput during high-traffic intervals.
