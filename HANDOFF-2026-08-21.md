The edit (~line 679) replaces `serde_json::to_string(&request_dynamic)` with
`serialize_with_options(.. use_proto_field_name(true).skip_default_fields(false))`.

**Why:** plugin handlers read args by *proto* field name (`require_str(&args,
"provider_id", ..)`), but prost-reflect's default Serialize emits canonical
protobuf JSON — camelCase. So `provider_id` arrived as `providerId` and every
multi-word argument looked absent. Single-word fields (`provider`) are identical
in both spellings, which is exactly why ListModels filtering works and
SetProvider does not.
