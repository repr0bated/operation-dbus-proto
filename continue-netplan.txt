specifically to convert a working wg-quick config into systemd-networkd files,  
because systemd-networkd has native WireGuard support and can manage the        
interface itself. The tool’s stated purpose is to bridge from wg-quick format   
to networkd format, and its author explicitly positions it as a migration path  
when you want networkd to own the tunnel instead of leaving it unmanaged.       
                                                                                
That means your cleaner model is:                                               
                                                                                
Netplan persists the OVS bridge.                                                
                                                                                
Netplan or straight systemd-networkd manages WireGuard natively.                
                                                                                
wg-quick stops owning those interfaces at boot.                                 
                                                                                
dinit can still do any post-network logic, but not basic WireGuard creation.    
                                                                                
Bluntly: that is better than trying to have wg-quick create wg0/wgcf first and  
then hoping Netplan adopts them later. Netplan is built to generate backend     
config, and systemd-networkd already supports WireGuard directly, so converting 
 the configs is the more coherent path.                                         
                                                                                
The one caveat is important: wg2nd converts almost all wg-quick configs, but it 
 does not automatically reproduce wg-quick’s default-route firewall behavior    
unless you separately generate/install equivalent nftables rules. That          
limitation is documented by the project itself.                                 
                                                                                
So for your use case, the sane architecture is:                                 
                                                                                
Start with your known-good wg-quick config.                                     
                                                                                
Convert it with wg2nd.                                                          
                                                                                
Let systemd-networkd own the WireGuard interfaces at boot.                      
                                                                                
Let Netplan persist the OVS bridge side.                                        
                                                                                
Use dinit only for the glue step, such as adding already-networkd-managed       
interfaces to OVS, if you still want that topology.                             
                                                                                
The only caution I’d keep repeating is wgcf: if by wgcf you mean Cloudflare     
WARP via the wgcf tool, that is still a standard WireGuard-style config at the  
tunnel level, so conversion is possible in principle, but the broader           
WARP-specific lifecycle is outside what wg2nd itself promises. That last point  
is an inference from the documented scope of wg2nd, which is conversion of      
wg-quick WireGuard configs, not WARP account/session management.                
                                                                                
So the answer is:                                                               
                                                                                
Yes — using wg2nd makes your earlier idea much more viable, because now the     
interfaces can be created natively by systemd-networkd at boot instead of by    
wg-quick.                                                                       
                                                                                
What I would do:                                                                
                                                                                
keep Netplan for ovsbr0 persistence                                             
                                                                                
convert wg0.conf and wgcf.conf with wg2nd                                       
                                                                                
let networkd bring those up                                                     
                                                                                
then use one small dinit service to attach them to OVS if you still want them   
as ports                                                                        
                                                                                
That is a much cleaner stack than mixing wg-quick boot-time creation with later 
 Netplan expectations.
