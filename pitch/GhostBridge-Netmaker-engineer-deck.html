System thesis

A mesh is more than transport when it becomes the root of evidence.

GhostBridge treats Netmaker/WireGuard identity as link zero. Every governed action carries identity, mutation, schema, policy authority, trace, footprint, and semantic meaning. AI can reason over the evidence, but only the governed layer can mutate state. gRPC is the service plane that moves these contracts between Rust components over Unix domain sockets and controlled bridge paths, and Tonic is the Rust implementation of that gRPC transport.

Transport

Netmaker mesh carries the trusted path. Xray routes by Server Name Indication (SNI) and injects identity/accountability headers.

Identity

WireGuard peer material anchors session_id = Argon2(PSK, salt = WG_pubkey).

Evidence

The Snowball ledger is the immutable, tamper-evident memory-loop source: accepted actions are appended as hash-linked blocks, then replayed into semantic projections for retrieval and confrontation.

Core philosophies

What cannot be verified does not exist.

No verified schema, no existence

If a thing has no validated schema, it is not a real object in this system. That is the primary attack boundary and the primary source of truth.

Single source of truth

Schema-backed D-Bus control-bus projection is authoritative. User interface, gRPC, Model Context Protocol (MCP), search, and evidence are projections or transports, not alternate realities.

Use live resources

Build from working realtime resources that already exist. Do not mine past user data to index, compile, or replay as a substitute for live state.

Reality first

Prefer observed state, live traces, and actual object graphs over claims, intentions, or clean-room abstractions.

Future from present

The future is shaped by what is already running, measurable, and schema-valid today. That is how the platform stays grounded.

No speculative resources

We do not search for hypothetical resources to invent later. We use current realtime resources to build the next state from the current one.

Core runtime architecture

One control plane. One schema truth. Multiple transport surfaces.

Rust control plane
The whole system is a Rust control plane first: state, validation, bridges, and projections live in compiled Rust crates rather than ad hoc scripts.
D-Bus projection
Live authority is the D-Bus control bus at org.opdbus.projection; plugin objects publish under /org/opdbus/v1/plugins/<name>.
PluginSchema
Plugin is schema. If a validated schema/object is missing, the thing does not exist in the system.
The Sled
1:1 shared-memory layout for identity/state projection; schema-guided direct read/write semantics.
The Shuttle
Rust bridge/courier between D-Bus, gRPC, vector search, state projection, and UI surfaces.
The Snowball
Immutable, tamper-evident session ledger and memory-loop source. Chat turns, tool actions, and approvals are appended here, then replayed into semantic search and UI evidence.
Strike / Etch
Hash generation and footprint binding for blocks, traces, and payloads.
gRPC / Unix
Internal service RPC over Unix domain sockets or controlled bridge paths; D-Bus remains authority, gRPC is transport.
gRPC bridge
Service-to-service APIs, event-chain search, assistant surfaces, and internal contracts flow over gRPC when they are not directly D-Bus-bound.
Why these choices

Tonic, Gemma, and ZeroClaw each fill a specific role.

Tonic

The gRPC implementation in Rust. It fits the control plane because it keeps service transport type-safe, schema-driven, and local-socket friendly. Tonic reflection lets runtime clients discover the service surface without needing a local .proto file.

Gemma

The traffic classifier/router for the front of the pipeline. Gemma decides what a request is before Xray/OpenFlow decide where it should go.

ZeroClaw

Policy-aware model dispatch. It is not a generic wrapper; it centralizes model routing by cost, reasoning depth, provider, structure, and policy so the rest of the stack stays schema-native.

Authority plane

Plugin is schema. D-Bus is authority. A.N.N.A. notarizes the state.

This is the control contract that keeps the rest of the platform honest: D-Bus publishes the object, PluginSchema defines the shape, A.N.N.A. Scribe notarizes identity and trace, and the Law Firm enforces policy references on top.

Netmaker hardening pattern

Control services become socket-backed, identity-gated surfaces.

The pattern treats netmaker, netmaker-mq, and netmaker-ui as loopback/socket services. Incus exposes Unix sockets under /run/netmaker. Xray terminates and routes by Server Name Indication (SNI) behind WireGuard identity. The intended public posture is no direct Netmaker service port.

Accountability loop

Chatbot on top. Semantic evidence underneath.

Header provenance

Xray/OpenClaw metadata carries X-Ghostbridge-Footprint, X-Ghostbridge-Trace-ID, or WireGuard pubkey identity.

Snowball block

Accepted action becomes a hash-linked block with previous hash, event hash, trace id, footprint, subid, actor, and capability.

Semantic projection

The UI queries both Qdrant and Cozo, then combines semantic similarity and graph context into one unified response. Voyage embeds blocks, docs, transcripts, and chat turns so both stores can be rebuilt from the same evidence.

Cross-examination

The model explains. The evidence pane verifies. If the explanation drifts, semantic receipts contradict it.

gRPC plane

gRPC is the high-throughput service plane between the governed components.

Transport

gRPC runs over Unix domain sockets or controlled local bridge paths when the service should stay inside the host boundary.

Bridge

The Shuttle and bridge services move requests between D-Bus authority, memory/state, and higher-level assistants without inventing a second control plane.

Search/API

Semantic search, chat tools, and assistant integration use gRPC surfaces where D-Bus itself is not the best transport.
