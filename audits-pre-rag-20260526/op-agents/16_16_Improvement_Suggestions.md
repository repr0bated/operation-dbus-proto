1. **CRITICAL: Path Traversal Bypass via String Prefix Validation** | The validation function `validate_path` used by the legacy agents only checks if the input path string starts with an allowed directory (such as `/tmp` or `/home`). Because it does not canonicalize the path or verify that it is free of parent directory references (`..`), an attacker can pass a path like `/tmp/../../../etc/shadow` to bypass the directory restriction and access, read, or execute files anywhere on the host system. | `crates/op-agents/src/agents/base.rs:201`

2. **CRITICAL: JSON Injection via Manual Format-Based Serialization** | In `MemoryAgent`, the persistent memory cache is serialized using manual string interpolation (`format!`) without escaping control characters, double quotes, or newlines. An attacker storing a value containing quotes and custom JSON syntax (e.g., `", "hacked": true, "dummy": "`) can successfully corrupt the JSON database, inject arbitrary keys, or spoof other memory entries during deserialization. | `crates/op-agents/src/agents/orchestration/memory.rs:228`

3. **ARCHITECTURE: Monolithic Crate Bloat and Compilation Bottleneck** | The crate mixes core orchestration frameworks, HTTP routing, D-Bus service bindings, code generators, and over 50 domain-specific agent implementations (such as `DjangoProAgent` and `QuantAnalystAgent`). This high coupling results in very slow compilation times and makes it impossible to deploy slim, tailored agent environments. These components should be decoupled into a core traits crate and separate pluggable agent implementations. | `crates/op-agents/src/lib.rs:43`

4. **ARCHITECTURE: Bypassing Sandbox Execution in Legacy Agents** | Legacy agents like `CodeReviewerAgent` and `DebuggerAgent` execute system commands directly via `std::process::Command` instead of utilizing the `SandboxExecutor` abstraction. This duplicates process execution logic and completely bypasses configured resource limits (timeouts, CPU, and memory limits), leaving the host vulnerable to resource exhaustion or denial-of-service. | `crates/op-agents/src/agents/analysis/code_reviewer.rs:25`

5. **API ERGONOMICS: Stringly-Typed Errors for Agent Instantiation** | The `create_agent` factory returns raw `String` errors when an agent fails to initialize or is not found. This prevents callers from programmatically matching on failure variants. Replacing this with a structured enum (e.g., `enum AgentCreationError`) derived via `thiserror` would make error handling robust and ergonomic. | `crates/op-agents/src/lib.rs:43`

6. **API ERGONOMICS: Awkward Argument Construction with simd-json OwnedValue** | The `AgentTask` struct defines its configuration fields using `HashMap<String, simd_json::OwnedValue>`. Building an `OwnedValue` manually is highly verbose and error-prone. Introducing a builder pattern or serializing typed structs directly via `serde` would prevent type mismatches and eliminate boilerplate. | `crates/op-agents/src/agents/base.rs:31`

7. **PERFORMANCE: Heap Allocation and Boxing Overhead in Catalog Queries** | `builtin_agent_descriptors` instantiates and boxes more than 50 agents on the heap merely to extract their static descriptors (name, description, and operations). This incurs high CPU and memory overhead on every catalog lookup. These descriptors should be generated statically at compile time or cached within a lazy-loaded static map. | `crates/op-agents/src/agent_catalog.rs:88`

8. **PERFORMANCE: Unnecessary Memory Allocations in Output Sanitization** | `sanitize_output` takes a slice (`&str`) and returns an owned `String`. If the string does not exceed `max_size` (which is true for the vast majority of runs), it copies the entire string buffer. Utilizing `Cow<'a, str>` or `bytes::Bytes` would enable zero-copy operation, drastically reducing allocation overhead for large outputs. | `crates/op-agents/src/security/validation.rs:197`

9. **OBSERVABILITY: Raw Print Macros in Generated Code** | The code generation template uses raw `println!` macros to log incoming tasks and parameters. This bypasses the active `tracing` subscriber, rendering these logs invisible to production logging systems, formatters, and metrics exporters. The template should be updated to use structured `tracing::info!` macros. | `crates/op-agents/src/generator/template.rs:555`

10. **OBSERVABILITY: Missing Structured Fields in Production Tracing** | D-Bus service instantiation and management events are logged using formatted string interpolation instead of structured fields. Adopting structured fields (e.g., `info!(agent_type = ?agent_type, bus = ?bus_type, "Starting D-Bus agent")`) allows telemetry aggregators like Datadog or ELK to index and query log events efficiently. | `crates/op-agents/src/dbus_service.rs:327`

11. **STORAGE: Inefficient Full-File persistent Reads/Writes** | `MemoryAgent` loads, parses, and writes the entire cognitive database flat file `/var/lib/op-dbus/memory_cognitive.json` on every single query or storage action. This causes severe I/O bottlenecks as the database grows and exposes the system to data loss if a crash occurs during a write. It should be refactored to use an embedded key-value store such as `Sled` or `CozoDB` (which are already workspace dependencies) for transactional, page-level persistence. | `crates/op-agents/src/agents/orchestration/memory.rs:94`
