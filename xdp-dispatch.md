When you run a custom XDP program alongside Open vSwitch (OVS) using AF_XDP, you must utilize the multi-program XDP dispatch functionality. Because AF_XDP creates sockets in userspace by redirecting packets using a specialized map, your custom XDP program and the OVS-supplied program must co-exist on the same network interface.How it Works TogetherTo achieve line-rate kernel bypassing without breaking OVS’s functionality, you cannot load two independent XDP programs blindly onto the same network interface.Instead, you have to chain them using libxdp (xdp-dispatcher or xdp-loader):The Custom XDP Program: This is your primary logic (e.g., firewall filtering, DDoS protection). It executes, evaluates the packet, and determines its fate (e.g., XDP_PASS or XDP_REDIRECT).The OVS XDP Program: If your custom XDP program passes the packet (XDP_PASS), it gets handed down the chain to the OVS XDP program. The OVS XDP program intercepts the packet at the lowest possible layer and redirects it (XDP_REDIRECT) into the AF_XDP socket (the afxdp netdev type in OVS).The XDP Dispatcher: This Linux mechanism permits multiple BPF programs attached to the same hook point to be chained together sequentially without overwriting each other.Key Technical Challenges & SolutionsHardware Queues: An AF_XDP socket typically binds directly to a specific hardware RX/TX queue. If your custom program is also trying to bind to queues, make sure the Network Interface Card (NIC) supports multiple queues, and that you map queues correctly using an XSKMAP.UMEM Management: If your custom application and OVS are running separate AF_XDP logic, they need to know how to handle the UMEM memory buffer. OVS re-uses the dpif-netdev userspace datapath to handle packet processing.Execution Modes: Make sure your driver handles both XDP_REDIRECT and either the "Native/Driver" or "Generic" XDP mode. "Native with Zero-Copy" is ideal for maximum line-rate performance.Best Practices & SetupEnable AF_XDP in OVS: Make sure your Open vSwitch is compiled with libbpf and --enable-afxdp support.Deploy xdp-tools: Use the XDP Tools GitHub Repository to manage the dispatcher and load your custom XDP object files without interfering with OVS.Bind OVS correctly: Attach your physical interface to the OVS bridge using the afxdp interface type rather than the standard DPDK or kernel types.
