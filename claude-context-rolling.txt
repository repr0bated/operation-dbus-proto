## 2. Architecture Clarification — Socket Networking + gRPC

### Key Architectural Facts
- **ALL traffic is gRPC, not raw HTTP.** Browsers connect via gRPC-Web (tonic supports this with `tonic_web::enable` and `accept_http1(true)`)
- **No NICs on containers** — unix socket networking only. All inter-service communication via unix domain sockets
- **xray uses tag routing** — all traffic routed to gRPC bridge (zeroclaw at `127.0.0.1:18789` inside wg-xray)
- **Oracle VPS is decoy front by design** — DNAT forwards to hypervisor via WG tunnel (10.0.0.2)
- **OVS bridge handles obfuscation** (not xray Reality) — xray Reality is a separate transport layer
- **Two controller tables planned**: xray for transport routing, OVS for domain routing

### Network Flow (External → Service)
```
Browser → gRPC-Web
  → Oracle VPS :443 (DNAT)
  → WG tunnel → 10.0.0.2 :443
  → Incus proxy → wg-xray container :443
  → xray op-tls inbound (VLESS+TLS)
  → fallback → 127.0.0.1:18789 (zeroclaw gRPC bridge)
  → unix sockets → individual service backends
```

## 3. IdentitySled / GhostbridgeInterceptor Integration

### Architecture
- The **GhostbridgeInterceptor** in `op-grpc-bridge` requires `x-ghostbridge-footprint` and `x-ghostbridge-trace-id` headers on EVERY gRPC request
- The **sled** is a LIVE LEDGER at `/dev/shm/plugin_schema.dat` — footprint changes with every mutation
- Footprint = Blake3 of `wg_pubkey + schema_catalog_hash + mutation_index + source_port`
- xray gRPC outbound injects sled headers via gRPC metadata

### Sled State Issues & Fixes
- The sled was **missing** from `/dev/shm` on host — copied from `/var/lib/op-dbus/plugin_schema.dat`
- **Static xray config will go stale** as sled mutates — need dynamic regeneration (pending work)

### Current Sled Values (as of session end)
- `footprint`: `8312d5be84544a075cef2206d544025f912c72063b1275ba6dd818fe9948d516`
- `trace_id`: `ac75287b70274ba3aa78a84d39094182` (changes on each `--refresh`)

### Implications
- Every time the plugin tree mutates, the footprint changes
- xray config must be dynamically regenerated to inject current sled values
- The "sled is live" principle means the static JSON at `/etc/xray/config.json` is already stale

### D-Bus Architecture Rule
- **"The plugin IS the schema"** — if an object doesn't exist under `/org/opdbus/v1/plugins/`, a plugin needs to be created
- Every plugin is a D-Bus object at `/org/opdbus/v1/plugins/<name>`
- Read state through D-Bus. Mutate state through D-Bus. If there is no D-Bus object, the thing does not exist.
